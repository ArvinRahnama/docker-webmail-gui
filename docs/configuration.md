# Configuration

Every setting lives in one `.env` file at the repository root, generated
by `installer/install.sh` and read by `docker/compose.yaml`.

**[`.env.example`](../.env.example) is the authoritative reference** —
every variable, what it means, whether it is required, and its default.
That file is checked against the code's own schema, so it cannot quietly
drift. This page deliberately does not repeat it. What it covers instead
is the handful of settings where the _right_ value depends on how you are
deploying, and where getting it wrong produces a confusing symptom rather
than an error.

## How a setting is resolved

`install.sh` resolves each value in one order:

1. The installer's own environment — `PORT=8080 ./installer/install.sh`
2. The existing `.env`, if there is one
3. The documented default

Rule 2 is what makes the installer safe to re-run: edit `.env` by hand,
run the installer again, and your edit survives. Keys the installer does
not manage are copied across verbatim under their own heading. No
existing secret is ever regenerated.

To change a setting: edit `.env`, then re-run `./installer/install.sh`.
Restarting the containers without it works too, but the installer also
rebuilds and re-checks health.

## The four settings that actually need a decision

### `COOKIE_SECURE` and TLS — the one that silently locks you out

Default `true`, which is correct behind TLS and fatal without it.
Browsers refuse to store a `Secure` cookie over plain `http://`, with one
exception: `localhost` / `127.0.0.1`. So the URL the installer prints
works, and the same panel reached over a LAN address or a hostname on
plain HTTP will accept your login and then appear to do nothing at all —
no error, just a bounce back to the login page.

Pick one:

- **Recommended.** Put a reverse proxy in front, terminate TLS there, set
  `BIND_ADDRESS=127.0.0.1` so the published port exists only for that
  proxy, and leave `COOKIE_SECURE=true`.
- **Trusted LAN, no TLS.** Set `COOKIE_SECURE=false`. You are choosing to
  send a session cookie over plaintext on your own network.

`install.sh` prints a warning about this on any install where
`COOKIE_SECURE` is left on.

### `BIND_ADDRESS` — who can reach the published port

`0.0.0.0` by default, which publishes on every interface: right for a
plain LAN install with no proxy. Set it to `127.0.0.1` when a reverse
proxy on the same host is the only thing that should reach it.

### `DMS_CONTAINER_NAME` / `DMS_CONTAINER_LABEL` — finding your mail server

This project does **not** deploy `docker-mailserver`; it manages one that
already exists. The broker resolves that container's identity itself,
from this configuration — the web tier never sends a container id.
Default `mailserver`. If yours is named something else, set it; if it is
easier to match by label, set the label instead.

Container-name matching is anchored, not substring: a container called
`mailserver-old` will not be picked up by accident.

### `ENABLE_EXEC_CONSOLE` — off by default, and should stay off

Enables the diagnostic command console. Even enabled, it is not a shell:
the client sends a symbolic key naming one of a fixed set of
zero-argument commands whose argv the broker owns. There is no way to
pass an argument, a path or a command string. Leave it off unless you
specifically need it.

`ENABLE_HSTS` follows the same "on by default, turn it off only for a
deliberate plain-HTTP install" pattern as `COOKIE_SECURE`.

## Secrets

`COOKIE_SECRET` and `BROKER_SHARED_SECRET` are generated by the installer
with a CSPRNG (`openssl rand -hex 32`, falling back to `/dev/urandom`)
and never regenerated on a re-run — rotating either would invalidate
every live session, or cut the web tier off from the broker until both
containers restarted together.

`.env` is written mode 600. It holds both secrets and, until you clear
them, the bootstrap admin credentials. Clear
`BOOTSTRAP_ADMIN_EMAIL`/`BOOTSTRAP_ADMIN_PASSWORD` after your first
successful login — the installer's closing message says so too.

`RSPAMD_PASSWORD` is the Rspamd controller password, if yours has one.
Without it, Rspamd features report `Unavailable` rather than guessing.

## A note on values containing `#`

Compose's env-file parser treats `#` as starting a comment when preceded
by whitespace. A password containing ` #` will be truncated. Avoid it, or
quote the value.
